# Go (Golang) — Docker Project Structure & Best Practices

> Go produces statically compiled binaries that run without any runtime dependencies. This makes Go ideal for minimal Docker images — a ~10MB binary in a `scratch` or `distroless` container, no OS overhead.

---

## Project Structure

```
my-go-service/
├── Dockerfile                   # multi-stage build
├── .dockerignore
├── docker-compose.yml           # local development stack
├── go.mod                       # module definition + dependencies
```

## go.mod & go.sum Explained

**go.mod — module definition:**
```go
module github.com/org/my-service    // module path (used in imports)

go 1.22                             // minimum Go version required

require (
    github.com/gin-gonic/gin v1.9.1
    github.com/lib/pq v1.10.9
    github.com/prometheus/client_golang v1.17.0
)

require (
    // indirect dependencies (transitive)
    github.com/bytedance/sonic v1.10.2 // indirect
)
```

**go.sum — cryptographic lock file:**
```
github.com/gin-gonic/gin v1.9.1 h1:4idEAncQnU5cB7BeOkPtxjfCSye0AAm1R0RVIqJ+Jmg=
github.com/gin-gonic/gin v1.9.1/go.mod h1:hPrL7YrpYKXt5YId3A/Tnip5kqbEAP+KLuI3SUcPTeU=
```
- go.sum ensures every `go mod download` gets exactly the same dependency version (no supply chain attacks)
- Both files should always be committed to version control
- Never manually edit go.sum — it's generated by `go mod tidy`

## Optimized Dockerfile — Multi-Stage

```dockerfile
# ─── Stage 1: Download dependencies ─────────────────────────────
# Separate stage so dep download is cached independently
FROM golang:1.22-alpine AS deps
WORKDIR /build
# Only copy module files — changes only if deps change
COPY go.mod go.sum ./
RUN go mod download

# ─── Stage 2: Build ──────────────────────────────────────────────
FROM deps AS builder
# Copy source code (changes frequently — after dep download)
COPY . .
# Build flags:
#   CGO_ENABLED=0  → static binary (no C runtime dependency)
#   GOOS=linux     → cross-compile for Linux if building on Mac/Windows
#   GOARCH=amd64   → target x86_64
#   -ldflags "-s -w" → strip debug info → smaller binary (~30% reduction)
#   -trimpath      → remove local build paths from binary
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -ldflags="-s -w" -trimpath \
    -o /build/server ./cmd/server

# ─── Stage 3: Final minimal image ────────────────────────────────
# Option A: scratch (smallest — just the binary)
FROM scratch AS final
COPY --from=builder /build/server /server
# CA certs needed for HTTPS outbound calls
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
# /etc/passwd needed if you want to set a non-root user in scratch
COPY --from=builder /etc/passwd /etc/passwd

EXPOSE 8080
USER nobody                        # run as unprivileged user
ENTRYPOINT ["/server"]

# Option B: distroless (slightly larger, but includes timezone data + user accounts)
# FROM gcr.io/distroless/static-debian11:nonroot AS final
# COPY --from=builder /build/server /server
# EXPOSE 8080
# ENTRYPOINT ["/server"]
```

## docker-compose.yml — Local Development Stack

```yaml
services:
  api:
    build:
      context: .
      target: final               # use the final production stage
    image: my-service:local
    ports:
      - "8080:8080"
    environment:
      - DB_HOST=postgres
      - DB_PORT=5432
      - DB_NAME=myapp
      - DB_USER=${DB_USER:-postgres}
      - DB_PASS=${DB_PASS:-secret}
      - LOG_LEVEL=debug
    depends_on:
      postgres:
        condition: service_healthy
    restart: unless-stopped

      POSTGRES_DB: myapp

      POSTGRES_PASSWORD: secret

      test: ["CMD-SHELL", "pg_isready -U postgres"]

      timeout: 3s
      retries: 5

    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redisdata:/data

  pgdata:
  redisdata:
```

## Build Commands

```bash
# ─── Local development ────────────────────────────────────────────
go run ./cmd/server                             # run without building a binary
go build -o bin/server ./cmd/server             # build binary
go test ./...                                   # run all tests
go test -race ./...                             # with race detector
go vet ./...                                    # static analysis

# ─── Module management ────────────────────────────────────────────
go mod tidy                                     # add missing, remove unused deps
go mod download                                 # download deps to local cache
go mod vendor                                   # vendor all deps to ./vendor/
go list -m all                                  # list all dependencies

# ─── Docker build ─────────────────────────────────────────────────
docker build -t my-service:local .
docker build --target builder -t my-service:debug . # stop at builder stage (has go toolchain + shell)
docker run --rm -it my-service:debug sh             # debug the builder stage

# Multi-platform build:
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t registry.example.com/my-service:v1.0 \
  --push .

# ─── With docker-compose ──────────────────────────────────────────
docker compose up -d                            # start all services
docker compose up -d --build                    # rebuild + start
docker compose logs -f api                      # stream API logs
docker compose exec api sh                      # shell into running container
```

## Go-Specific Docker Best Practices

**1. Use `-ldflags="-s -w"` always:**
```bash
# Without flags: 15MB binary
# With -s -w:    10MB binary (removes DWARF debug info and symbol table)
go build -ldflags="-s -w" -o server .
```

**2. Embed version at build time (not as env var):**
```go
// main.go
var Version = "dev"  // set by ldflags at build time

// Build:
// go build -ldflags="-X main.Version=$(git describe --tags)" -o server .
```

**3. Health check endpoint for container orchestration:**
```go
http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
    // Check DB connection, cache, etc.
    w.WriteHeader(http.StatusOK)
    w.Write([]byte(`{"status":"ok"}`))
})
```

**4. Handle SIGTERM for graceful shutdown:**
```go
server := &http.Server{Addr: ":8080"}

go func() {
    sigChan := make(chan os.Signal, 1)
    signal.Notify(sigChan, syscall.SIGTERM, syscall.SIGINT)
    <-sigChan
    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()
    server.Shutdown(ctx)  // stops accepting new connections, waits for in-flight
}()

server.ListenAndServe()
```

**5. Use `tini` if spawning child processes:**
```dockerfile
FROM alpine AS final
RUN apk add --no-cache tini
COPY --from=builder /build/server /server
ENTRYPOINT ["/sbin/tini", "--", "/server"]
# tini reaps zombie child processes — important if your app forks
```

## Interview Q&A

**Q: Why is Go so good for containerization?**
Go produces statically compiled binaries by default (with `CGO_ENABLED=0`) — the binary contains everything it needs and doesn't depend on shared libraries, libc, or a runtime. This means the final Docker image can be `scratch` (literally empty) plus just the binary — resulting in 5-15MB images. No OS, no shell, no attack surface beyond the application code itself. Compare to JVM (needs JRE ~200MB) or Python (needs interpreter + all packages). Startup time is also sub-100ms since there's no JIT compilation or interpreter warm-up.

**Q: What does CGO_ENABLED=0 do and when would you need CGO enabled?**
`CGO_ENABLED=0` disables Go's C interoperability layer and produces a fully static binary. When disabled: no C standard library dependency, single binary, runs on any Linux distro regardless of glibc version. You need CGO when your code (or a dependency) calls C libraries — e.g., SQLite (`mattn/go-sqlite3`), some crypto operations, or `net` package's DNS resolution in some configurations. If you need CGO in a Docker image, use a `distroless/base` image (which has libc) rather than `scratch`.

**Q: What's go.sum and why must it be committed to version control?**
`go.sum` is a cryptographic audit log — it records the SHA-256 hash of every specific version of every dependency ever downloaded. When you run `go mod download`, Go verifies each dependency matches its hash in go.sum. Committing go.sum ensures: (1) reproducible builds — everyone gets exactly the same dependency code, (2) supply chain security — if a malicious version is substituted upstream, the hash mismatch is caught immediately. Without go.sum, a "v1.2.3" dependency could silently serve different code to different developers.
